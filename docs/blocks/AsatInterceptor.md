# 反卫星拦截塔（ASAT Interceptor）

> **它自己看不见卫星**——目标来自[卫星定位器](SatelliteLocator.md)发布的情报，按信号编码配对。
> 先读那一篇会更容易理解本文的平衡部分。

## 1. 一句话

2×2 炮塔：按**定位情报**锁定敌方在轨卫星，两发击落（每发 200 伤害），
每发从电网电池扣 40000 电力，锁定速度取决于所在位置的**信号可用度**。

## 2. 为什么是炮塔，却不开子弹

它继承 Mindustry 的 `Turret`：炮管转向、装填条、射界、开火前炮口对准、悬停面板的炮塔统计、
逻辑处理器控制——炮塔该有的都有。但开火**不创建子弹**：卫星单位在第一阶段就被定成
`hittable = false` / `targetable = false`（见 `src/silicon/content/SatelliteUnits.java`），
引擎的索敌与所有常规伤害路径对它们失明，子弹会直接穿透。

这是**有意**的：卫星不能被普通炮塔顺手打下来，否则任何覆盖敌基地的卫星都活不过一分钟。
代价是击落必须由 scripted 伤害（`unit.damage()`）完成，血量 400 就是"拦截成本"。

为此覆写了三个方法，原因都写在代码注释里：

| 覆写 | 为什么 |
|---|---|
| `findTarget()` | 目标来自 [`SatelliteIntel`](SatelliteLocator.md) 情报（且引擎索敌本就看不到卫星） |
| `validateTarget()` | 基类默认走 `Units.invalidateTarget`，对卫星一律判"失效"——不覆写的话，刚拿到的目标会被立刻清掉 |
| `shoot(BulletType)` | 不发子弹，扣电 + 结算伤害 |

## 3. 四道门（缺一道就打不出去）

| 门 | 条件 | 缺了会怎样 |
|---|---|---|
| **情报** | 本队有一座同编码的定位器在工作 | 没有目标来源，炮塔空转 |
| **射程** | 目标在 48 格内 | 目标在情报里但超出射程，继续等它飞近 |
| **锁定** | 持续瞄准 1~6 秒（由信号可用度决定） | 装填不推进，炮口压不下来 |
| **电力** | 电池里 ≥ 40000 | 待机等电池攒够（不空放） |

## 4. 参数

| 项 | 值 | 说明 |
|---|---|---|
| 射程 | **48 格** | 已不是平衡杠杆——"看不看得见"由定位器决定，射程只是布局余地 |
| 目标来源 | 绑定编码的定位情报 | 配置面板列出本队工作中的定位器编码，点选绑定 |
| 射速 | **3 秒 / 发**（`reload = 180`） | 两发 6 秒击落 |
| 每发伤害 | **200** | 400 血 = 两发 |
| 每发电力 | **40000** | 从电网**电池**扣；击落一颗 = **8 万电力** |
| 锁定时间 | **1 秒 ~ 6 秒** | `lockTimeMin = 60` / `lockTimeMax = 360`，随可用度插值 |
| 可用度参考 | `qualityRef = 40` | 可用度 ≥ 40 即按最快锁定 |
| 常驻耗电 | 600/秒 | 待机也在烧电 |
| 建造成本 | 铜 500 · 铅 350 · 硅 450 · 钛 250 · 钍 150 · 塑钢 120 · 巨浪合金 80 | 血量 1200、护甲 6 |
| 预热 / 射界 | `minWarmup = 0.75`、`shootCone = 8°` | 开火前炮口必须基本对准，掠过的卫星不会一进射程就挨打 |

## 5. 可用度 → 锁定时间

```
锁定时间 = lockTimeMin + (lockTimeMax - lockTimeMin) × (1 − 可用度归一化)
```

可用度由 `SignalChannel.usableAll(team, x, y, …, scopeCode = 本塔编码)` 给出——
**与 H 覆盖、频谱面板完全同一个实现**。所以：

- 塔建在信号好的地方（信号源/中继器旁）锁定快；荒郊锁定慢，卫星可能已经飞走；
- 敌方可以用**信号干扰器**压制该信道的可用度，让锁定变慢甚至锁不上；
- 自己的卫星覆盖也能贡献可用度——"用自己的卫星给拦截塔供信号"是可行的建筑学。

## 6. 平衡：为什么拦截必须这么贵

卫星一侧的投入：

| 卫星一侧 | 量 |
|---|---|
| 发射中枢 | 铜 5000 · 硅 5000 · 塑钢 1250 · 巨浪合金 1250 |
| 生产 | 5000 电力/秒 × 60 秒 = **30 万电力** |
| 发射 | 轨道燃油（LEO 1000 ~ SSO 8000）+ 10000 缓冲电力 |

拦截一侧要付的代价：

| 拦截一侧 | 量 | 作用 |
|---|---|---|
| 每发电费 | 40000 × 2 发 = **8 万电力** | 一次性支出，与发射一颗卫星的电费同量级 |
| 常驻耗电 | 塔 600/秒 + 定位器 400/秒 | 长期成本，每个守点都要养 |
| 定位器 | 800 铜级材料 + 80 格探测范围 | **信息成本**：每片需要监控的空域都要一座定位器 |
| 锁定 1~6 秒 | 由信号可用度决定 | 信号差的区域打了折扣，逼玩家经营信号基建 |
| 预热 + 射界 | `minWarmup = 0.75`、`shootCone = 8°` | 掠过的卫星不会一进射程就挨打 |

**净效果**：击落一颗卫星的代价约在对方发射成本的 1/4 ~ 1/3，而且必须先建立**探测网络 + 信号覆盖 + 电力储备**
三件基建。卫星被打下来不再是免费的事，第二阶段的循环（发射贵 → 覆盖 → 拦截更贵 → 重发或护网）才成立。

可调旋钮，优先级从高到低：

1. `powerPerShot`（每发电费）与 `damagePerShot`（击落需要几发）；
2. `detectRadiusTiles`（定位器覆盖半径——直接决定要铺几座）；
3. `qualityRef` / `lockTimeMin` / `lockTimeMax`（信号依赖的强度，想弱化就调小 qualityRef）。
