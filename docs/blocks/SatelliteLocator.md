# 卫星定位器（Satellite Locator）

> 它给[反卫星拦截塔](AsatInterceptor.md)提供目标。塔的机制与平衡见那一篇。

## 1. 一句话

2×2 定位设施：探测 80 格内的**敌方在轨卫星**，把位置情报挂到自己的**信号编码**上，
供拦截塔按同一编码索取。

## 2. 为什么需要它

拦截塔打得远（48 格），但**看不见**天上的东西：卫星单位 `targetable = false`，引擎索敌看不到它；
`hittable = false`，常规伤害路径也碰不到它。所以塔的目标不能来自"天上所有的敌星"，只能来自一份
**外部情报**——这份情报就是本方块产出的。

这也把"打卫星"这件事从**火力问题**变成了**信息问题**：

| 想让拦截生效，必须凑齐 | 缺了会怎样 |
|---|---|
| 一座定位器，且它的探测范围覆盖到卫星轨道带 | 塔没有目标来源，只能空转 |
| 塔的编码 = 定位器的编码 | 塔拿不到那份情报 |
| 塔所在位置的**信号可用度**够高 | 锁定很慢（见下文） |
| 电网电池里攒够 40000 电力 | 打不出这一发 |

## 3. 参数

| 项 | 值 | 说明 |
|---|---|---|
| 探测半径 | **80 格** | 必须铺到卫星的轨道带上（LEO/MEO 会横扫全图，GEO 定点） |
| 刷新 | 10 tick 一次 | 卫星移动快，但不必每 tick 重扫整个单位表 |
| 情报有效期 | **180 tick = 3 秒** | 超过就当作过期（`SatelliteIntel.STALE_TICKS`），所以定位器断电/被拆后情报自动作废 |
| 耗电 | 400/秒 | 断电、被逻辑门关闭、被拆 → 立即撤稿 |
| 建造成本 | 铜 400 · 铅 300 · 硅 350 · 钛 200 · 中空玻璃 120 | 血量 700 |

## 4. 编码怎么配对

放置时自动分配一个**唯一编码**（与信号源同一套 4 位编码规则，`SignalSource.generateUniqueName()`）。
拦截塔的配置面板里会列出**本队所有正在工作的定位器编码**，点一下即可绑定——这就是"塔与定位器之间的信号通讯"
的入口；两者不需要相邻、不需要连线，甚至可以相隔大半个地图。

## 5. 可用度如何影响拦截

塔的**锁定时间**由它所在位置、它绑定编码的**信号可用度**决定：

```
锁定时间 = 1 秒（可用度 ≥ 40）      ← 信号好，炮口压得快
        → 6 秒（可用度趋近 0）      ← 信号差，锁定慢，卫星可能已经飞走
```

可用度取的是 `SignalChannel.usableAll(team, x, y, …, scopeCode = 塔的编码)`——
**与 H 覆盖、频谱面板完全同一个实现**，所以面板上看到多少，塔的锁定就按多少算，不会两处打架。

推论（也是这套设计有意思的地方）：

- 把拦截塔建在**信号覆盖良好**的地方（信号源/中继器旁边）比建在荒郊更快；
- 敌方可以反过来用**信号干扰器**压制你拦截塔所在信道的可用度，让锁定变慢甚至锁不上；
- 卫星的覆盖本身也贡献可用度——所以"用自己的卫星给拦截塔提供信号"是一种可行的建筑学。

## 6. 情报的形态

`SatelliteIntel` 以 `队伍 id + "|" + 编码` 为键保存一份快照（敌星实体 + 刷新时间），
定位器每 10 tick 覆盖写入，塔读取时检查"最近 3 秒内是否被刷新过"。因此：

- 定位器**断电/被关闭** → 撤稿（`updateTile` 里直接清）→ 3 秒内塔失去目标；
- 定位器**被拆** → `onRemoved` 清；换队 → `changeTeam` 清；读档/换图 → `SatelliteManager.reset()` 整体清空；
- 探测范围内**没有敌星** → 发布空快照（塔同样没有目标）。

## 7. 常量速查（`SatelliteLocator`）

| 常量 | 值 |
|---|---|
| `detectRadiusTiles` | 80 |
| `refreshInterval` | 10（tick） |
| `SatelliteIntel.STALE_TICKS` | 180（tick，= 3 秒） |
